Main Panel

Data source & inputs

RAG API Configuration

  • Fetch answer & contexts from RAG API — toggles live vs. manual mode
  • Endpoint, Timeout
  • Custom Header — name + masked value
  • Request Payload builder — add/remove keys, each “From JSON field” or “Hardcoded value,” with a live JSON preview
  • Answer / Contexts / Context Item Field — manual override for non-standard response shapes, with a reference panel of example shapes
  • Save Config — saves independently of LLM Configuration

Evaluation Mode

  • Single Case — Query, Ground Truth, and (if not using the API) Generated Answer + Contexts, one chunk per line
  • Batch (JSON file) — a file path field or file upload, with an inline schema reference that adapts to API vs. manual mode
  • Run Evaluation / Run Batch Evaluation — validates every required field and reports all problems at once
{"question": "...", "chat_history": []}

Transient LLM formatting errors retry once automatically; provider errors (401 / 404 / 429 / timeout) surface as plain-language fixes, not stack traces.

Results

Scores & diagnostics

Single Case

  • RAG API Response — collapsible Generated Answer / Contexts (API mode)
  • Scores — one tile per metric: 0–1 value, EXCELLENT/GOOD/MODERATE/POOR label, color-coded
  • Hover tooltip on a low score — the judge LLM's own reasoning for that specific case
  • Time Taken and token usage
  • Suggested Focus — which RAG stage (Retrieval / Augmentation / Generation) to fix, with a checklist

Batch

  • Live progress — per-case status (running / done / failed), updating in real time
  • Stop Evaluation — cancels cleanly, in-flight cases finish
  • Summary — average per metric, total time, total tokens
  • Suggested focus areas — aggregated across the batch, with combined fixes
  • Per-Case Results table + Show full details to expand every case
  • Clear batch results — resets for a new run

Note on providers

OpenAI and Azure AI Foundry are already built — just not switched on

The sidebar currently exposes only Azure OpenAI. Plain OpenAI and Azure AI Foundry both already have full credential handling and client-building support in the underlying configuration layer — enabling them as extra sidebar options is a small change, not new development.
